# Agent Note: Skills

Status: implemented — instructions for one kind of task, as folders the agent loads on demand, in Claude Code's format

## Problem

Some tasks need written instructions the agent should follow only when the task comes up:
tidying long-term memory, writing release notes the project's way. In the system prompt
they would cost tokens in every request; as code they would each be a feature. Claude Code
solves this with skills, and the user wants the same (2026-11-12), first for a memory
cleanup the user starts by hand, as Claude Code's is.

## Decision

- **A skill** is a folder with a `SKILL.md`: YAML frontmatter (`name`, `description`) and
  the instructions in Markdown, plus any files the instructions point to. This is Claude
  Code's format, so its skills work unchanged. Without a `name` the folder's name is used;
  without a `description`, the first paragraph of the instructions.
- **Where they are found**, later ones replacing earlier ones of the same name: Kayden's
  own (`src/kayden/skills/`), the user's (`<data dir>/skills/`), the project's
  (`<work folder>/.claude/skills/`).
- **The runtime owns them** (`runtime/skills.py`). With every request it rereads the
  folders in a thread, adds a section to the system prompt after the user's instructions
  that lists each skill's name and description, and offers the built-in tool
  `skill(name, arguments?)` (`api.SKILL_TOOL`), which answers with the skill's
  instructions and its folder. `$ARGUMENTS` in the instructions is replaced by the
  arguments; otherwise they follow the instructions. The model follows them with its other
  tools. With no skills, neither the section nor the tool is there.
- **The user starts one** by writing `/name` as a message: the prompt section tells the
  model to load that skill, the rest of the message being its arguments.
  `RuntimeAPI.skills()` lists them (`api.Skill`), so the terminal app, which has commands
  of its own, sends `/name` on when it is a skill and lists them with `/skills`. The
  desktop app has no commands, so the message goes as it is.
- **The first skill**, `consolidate-memory`, ships with Kayden: reread long-term memory,
  merge duplicates, fix or drop what is stale, with whatever tools the Memory in use
  offers. Nothing runs it automatically.
- A `SKILL.md` that cannot be read (bad YAML, an invalid name, no instructions) is skipped
  and written to the event log once (`skill_skipped`); loading a skill is logged (`skill`).

## Alternatives considered

- **A fifth module kind.** Nothing would be swapped: the skills are the pluggable part,
  and they are folders, not code.
- **A Tools module offering `skill`.** Self-contained, but frontends reach only the
  runtime, so they could not list skills, and choosing another Tools module would drop
  them.
- **Inject a skill's text when the user writes `/name`,** without a tool call. One
  request fewer, but a second way in, and the archive would hold text the user did not
  write. Claude Code also goes through its Skill tool.
- **List the skills in the tool's description** instead of the system prompt. No prompt
  change, but `/name` needs prompt text anyway.
- **Read the folders once per conversation.** Cheaper, but a skill being written would
  need a new chat to try; the read is a few small files.

## Consequences

- A new kind of task is a folder of text, not a change to Kayden, and Claude Code's skills
  can be copied in.
- Every request carries one line per skill, and Kayden's own skill is listed for
  everyone. A changed list starts a new prompt prefix for the provider's cache.
- PyYAML is a dependency, for the frontmatter.
- A project's skills are instructions from its repository, as its AGENTS.md is: opening an
  untrusted folder lets it talk to the agent. Tools stay behind the permission policy.
- Files a skill points to are outside the work folder unless it is a project skill, so
  reading them may ask for permission.
- Left out: skills that run in a sub-session, per-skill tool limits (`allowed-tools` is
  read and ignored), installing skills from a catalog, and a skill picker in the desktop
  app.
